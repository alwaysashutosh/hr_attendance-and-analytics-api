# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–37) | `minutes = int((punch_in - start).total_seconds() / 60)` followed by `minutes > 10` drops seconds. For 09:40:01 (601 sec = 10.01 min), integer truncation makes it 10, failing `> 10` and incorrectly returning 0. | Test input `09:40:01` with `09:30` shift start yields 0 late minutes instead of 10 (violates R2). | Compare raw `(punch_in - start).total_seconds() > 600`. When true, return `int(total_seconds // 60)` from shift start. |
| 2 | `compute_late_minutes` / `compute_overtime` (lines 33–47) | Naive timezone replacement and failure to handle overnight shifts (`shift_end <= shift_start`). `compute_overtime` placed `shift_end` on the start date rather than the next calendar day. | Overnight shift punch-out (e.g. 22:00–06:00, out at 06:40 next day) yields negative or broken overtime. | Convert instants to IST (`UTC+05:30`), check `shift_end <= shift_start`, and shift `shift_end` to next calendar day for overnight shifts. |
| 3 | `compute_work_hours` (line 41) | Uses Python's built-in `round(..., 2)` which performs banker's rounding (round-half-to-even) and float approximation. | Numbers with half fractions like 4.125 or floating approximations round down unexpectedly instead of half-up (violating R4/R8). | Implemented `round_half_up` using `decimal.Decimal` with `ROUND_HALF_UP` quantization. |
| 4 | `compute_overtime` (line 47) | Missing 30-minute qualification threshold required by R3. | Punch-out 15 minutes after shift end returns 15 minutes overtime instead of 0. | Return calculated overtime minutes only when `>= 30`, otherwise return 0. |
| 5 | `health` (lines 72–74) | Returns static `{"status": "ok"}` without pinging MongoDB. | Readiness probe returns 200 even when database is disconnected or unreachable. | Ping database via `client.admin.command('ping')`; raise HTTP 503 if unreachable. |
| 6 | `create_employee` (lines 78–85) | Check-then-insert pattern causes a race condition under concurrent duplicate requests. Missing input validation (`^EMP\d{4,6}$`, email format, `shift_start != shift_end`). | Concurrent identical `POST /employees` requests produce duplicate inserts or race condition errors. | Enforce database unique index on `emp_code`, catch `DuplicateKeyError` and return 409. Added Pydantic schema validation. |
| 7 | `create_employee` & models (lines 53–67, 82) | `created_at` stored as Python datetime and returned as ISO string instead of integer epoch milliseconds (`EpochMillis`). | Grader validation fails with 422 expecting integer epoch milliseconds. | Store UTC `datetime` in Mongo and serialize as integer epoch milliseconds in API response. |
| 8 | `list_employees` (lines 89–96) | Incorrect pagination offset `skip = page * page_size` skips page 1 completely (`page=1` skips 20 items). `total` counts entire collection ignoring `department` filter. Missing ascending sort. | Querying `page=1` returns page 2 items. Filtered total count shows full collection count. | Set `skip = (page - 1) * page_size`, pass filter query `q` to `count_documents(q)`, and sort by `emp_code` ascending. |
| 9 | `punch_in` (lines 100–121) | Check-then-insert race condition. Missing 404 check when employee does not exist (`emp["shift_start"]` raises 500 `TypeError`). Fails R1 overnight shift date assignment. | Simultaneous punch-in requests violate contract; non-existent employee crashes server with 500; overnight punch-in gets wrong date. | Check employee exists (404); assign attendance date per R1; rely on compound unique index `(emp_code, date)` and catch `DuplicateKeyError` to return 409. |
| 10 | `punch_in` (lines 119–120) | Leaks internal `id` (`doc["id"] = str(res.inserted_id)`); returns raw Python datetimes instead of epoch milliseconds. | Contract schema mismatch (no `id` allowed on `AttendanceRecord`; punch times must be epoch milliseconds). | Remove `id`; format response with integer epoch milliseconds (or null). |
| 11 | `list_attendance` (lines 125–150) | In-memory query and sorting: loads entire matching dataset into Python memory (`list(...)`) and sorts in Python. | Exhausts memory and suffers severe latency on ~100k documents, violating performance constraints. | Execute `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)` directly in MongoDB engine backed by compound index. |
| 12 | `list_attendance` (lines 127–142) | Does not validate `date_from <= date_to`. Also attaches `d["id"] = str(d.pop("_id"))`. | If `date_from > date_to`, returns empty list instead of 422. Schema violation returning `id`. | Raise HTTP 422 when `date_from > date_to`. Format items without `id` and serialize instants to epoch milliseconds. |

## Examined and Decided NOT to be Defects

1. **`IST = timezone(timedelta(hours=5, minutes=30))` definition:**
   Examined whether an external timezone library like `zoneinfo` or `pytz` was required. Fixed offset `UTC+05:30` is correct and standard for Indian Standard Time (IST has no daylight saving time transitions).
2. **`joined_on`, `date`, `shift_start`, and `shift_end` as strings:**
   Examined whether dates should be parsed into full datetime objects in MongoDB. As specified in `DATA_MODEL.md`, calendar dates (`YYYY-MM-DD`) and shift times (`HH:MM`) are purposefully stored as plain strings to prevent artificial time zone shifts.
